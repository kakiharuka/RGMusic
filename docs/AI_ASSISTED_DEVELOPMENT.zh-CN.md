# 如何借鉴 RG Music 用 AI 开发其他软件

本文面向准备在 RGDS Plus 上开发其他应用、并希望用 AI 辅助开发的开发者。

RG Music 是一个实际项目案例，不是通用硬件抽象层。它目前**只在 Anbernic RGDS Plus 上开发和测试**。其他设备、固件或应用必须重新做硬件和运行环境验证。

## 可以从这个项目借鉴什么

### APPS 安装与启动方式

可以参考以下文件，了解启动环境、资源路径和图标目录：

- `source/RG Music.sh`
- `tools/build_apps_package.ps1`
- `assets/README-APPS.txt`

不要假定其他启动器或固件使用完全相同的环境变量。

### 双屏应用结构

RG Music 将两块 `1024x768` 屏幕当成一张 `2048x768` 逻辑画布，再统一缩放绘制。这个设计适合双屏 UI，但屏幕顺序、旋转方向和实际坐标必须在目标设备上验证。

### 输入抽象

按键映射放在 `controls.lua`，触摸备用方案放在 `touch_evdev.lua`。这样的分层便于适配不同按键和触摸设备，不需要重写主逻辑。

### 后端子进程模式

网易云后端是独立的 Go 进程，LÖVE 客户端通过临时输出文件通信。这种方式把网络和账号处理与 UI 主进程隔离。

新项目不一定照搬文件通信，也可以使用本地 socket、HTTP、标准输入输出或共享内存。

### 外部播放器管理

`mpv.lua` 展示了：

- 每次播放使用独立 IPC socket 和 PID
- 取消任务和进程清理
- 播放状态轮询
- 加载、缓冲和确认播放的分层状态
- 使用 `idle-active` 判断 EOF

这些思路也可用于视频播放器、播客播放器、游戏启动器或其他媒体软件。

### 发布和隐私隔离

打包脚本展示了如何把源码和运行包分开，并排除账号、缓存、日志、音乐和测试文件。

## 建议的 AI 开发流程

### 1. 明确支持范围

只写实际测试过的设备型号和固件。没有实机验证的设备必须标记为“未验证”。

### 2. 建立能力清单

至少要验证：

- 屏幕数量、分辨率、顺序和方向
- 触屏和手柄事件设备
- 音频服务和输出设备
- 休眠与 Wi-Fi 行为
- 可写目录
- 可用运行库
- 启动器和安装包格式

### 3. 先做最小启动程序

在开发主功能前，先做一个最小程序验证：

- 两块屏幕能正确显示
- 能读取一个按键
- 能读取一个触摸坐标
- 能播放一个本地短音频
- 能写入并删除临时文件
- 能正常退出

先排除硬件问题，再开发界面，可以避免把硬件问题误认为 UI 问题。

### 4. 将 RG Music 当作子系统地图

| 需求 | RG Music 参考文件 |
|---|---|
| 启动环境 | `source/RG Music.sh` |
| 打包 | `tools/build_apps_package.ps1` |
| 本地扫描 | `library.lua` |
| 按键映射 | `controls.lua` |
| 触摸备用方案 | `touch_evdev.lua` |
| 后端子进程 | `netease.lua`、`source/RGMusicNetease` |
| 外部播放器生命周期 | `mpv.lua` |
| 双屏坐标 | `main.lua` |

### 5. 让 AI 按证据小步开发

先让 AI 阅读真实源码和设备输出，再按顺序推进：

1. 能力清单
2. 最小 Hello World
3. 输入输出验证
4. 音频和网络验证
5. 主功能开发
6. 打包和隐私检查

不要让 AI 假定 RGDS Plus 上的行为会自动适用于其他掌机。

## 可用的提示词

### 分析参考项目

```text
请把 RG Music 当作参考项目，输出一个子系统地图：哪些部分可以用于新的 ARM64 掌机应用，哪些是设备特定实现。不要假设其他设备兼容。
```

### 规划新应用

```text
我要在 RGDS Plus 上开发一个不同应用。请只把 RG Music 当作参考。先输出能力检查表和最小启动计划，在显示、输入、音频、存储和启动路径验证前不要写主功能代码。
```

### 复用子系统

```text
请研究 mpv.lua，提取可复用于其他媒体软件的生命周期模式，并区分通用模式和 RGDS Plus 特定假设，列出复用前必须完成的测试。
```

### 生成兼容性声明

```text
请审查项目并生成精确的兼容性声明，写明实际测试过的设备和固件，其他设备必须明确标记为未验证。
```

### 发布前隐私检查

```text
请检查仓库和发布包中是否有账号、Cookie、私人路径、音乐文件、日志和调试文件，只报告是否存在，不要输出凭证内容。
```

## 不要照搬的假设

其他设备不一定具有相同的：

- 屏幕顺序和方向
- 输入设备编号
- Wayland/X11 环境
- PulseAudio socket
- Wi-Fi 省电策略
- 系统休眠策略
- 可写目录结构
- 启动器格式
- 运行库版本
- CPU/GPU 性能
- 网络行为

## 最终目标

RG Music 的价值不在于让其他项目原样复制，而在于提供经过实机验证的双屏结构、进程隔离、媒体生命周期、打包方式和隐私隔离案例。其他项目可以借鉴模式，但必须重新验证硬件兼容性。
