# AI 辅助掌机软件开发指南

AI 可以显著加快开发速度，但前提是给它真实设备证据，而不是只给一个项目描述。本文记录 RG Music 开发过程中有效的协作方式。

## 准备上下文

建议向 AI 提供：

1. 设备型号、架构、内核、显示服务和音频服务。
2. 软件栈及准确版本。
3. 相关源码或完整文件树。
4. 掌机上的真实命令输出。
5. 涉及界面问题时提供截图或录屏。
6. 最小复现步骤和实际现象。
7. 已经尝试过什么，操作后发生了什么变化。

常用设备侦察命令：

```sh
uname -a
cat /proc/device-tree/model 2>/dev/null
cat /proc/bus/input/devices
ps aux
mount
iw dev
ip address
```

公开日志前，必须删除 IP、账号、Token、Cookie、设备 ID 等隐私信息。

## 推荐工作流

1. 让 AI 先检查实际文件和命令输出。
2. 要求它做最小诊断修改，而不是直接重写。
3. 在目标掌机上测试。
4. 把结果重新反馈给 AI。
5. 行为确实修好后再提交 Git。
6. 如果是设备特有问题，在 CHANGELOG 中记录回归点。

## 示例提示词

### 初始侦察

```text
这是一台运行 Wayland 的 ARM64 Linux 掌机。请阅读附件文件树和设备输出，找出可能影响 LÖVE 应用的运行环境、显示、输入和音频假设。先不要改代码，只列出下一步诊断命令。
```

### 硬件相关问题

```text
应用显示“正在播放”，但 mpv 已经不再推进。下面是设备上的 IPC 属性、进程列表和网络状态。请判断这是 mpv 生命周期、音频设备还是网络阻塞问题，做最小修改并说明验证方法。
```

### 打包

```text
根据这个源码目录和目标目录结构，编写可复现的打包脚本：只复制运行文件，检查依赖，排除账号、缓存、日志和测试数据，最后输出 SHA-256。
```

### 隐私审计

```text
审计整个压缩包和 Git 历史，查找 Cookie、会话令牌、账号 ID、昵称、本机路径、音乐文件和调试日志。只报告是否存在，不要输出任何敏感值。
```

## 安全边界

- 不要把 Cookie、密码、私钥或登录二维码发给 AI。
- 不要公开 `cookies.json` 或 `account.json`。
- 可以在设备上运行的命令，不要让 AI 凭空猜测结果。
- 调试输出放 `/tmp`，发布前删除。
- 源码仓库和构建压缩包分开管理。
- 发布前必须扫描压缩包中是否包含用户数据。
- 第三方许可证必须跟随源码和发布包。

## 为什么需要真实证据

嵌入式开发常见的问题来自桌面环境不会遇到的假设：Wayland 与 X11、IPv6、系统休眠、FAT32、音频会话生命周期、触摸事件上报方式等。一个真实命令输出往往比一大段描述更有价值。
